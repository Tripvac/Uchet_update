# Фиксация расхождений с ТЗ и принятым решениям (CONT-1)

В процессе разработки и проектирования Telegram-бота ПОБ «Учёт» возникли неоднозначные пункты технического задания. Ниже приведена таблица решений, принятых разработчиком для обеспечения стабильной и корректной работы системы.

## Таблица решений

| Пункт ТЗ / Спорный момент | Принятое разработчиком решение | Статус подтверждения |
| :--- | :--- | :--- |
| **Тема: «Повышенный взнос» vs «Часы ПК»** | Логика разделена по ролям пользователей (физлица, юрлица, учебные центры) с выдачей релевантных инструкций и разделов помощи. | Реализовано в коде и базе (`bot_content`) |
| **Разведение веток меню** | Создана древовидная структура навигации с историей шагов и кнопкой «Назад» (стек состояний). | Реализовано и проверено |
| **Отдельные экраны для юрлиц** | Созданы персональные информационные карточки для бухгалтеров, учебных центров и аутсорсинговых компаний. | Реализовано в базе контента |
| **Заглушки реквизитов и Kaspi QR** | Интегрированы актуальные реквизиты и текстовые инструкции по оплате через приложения банков (BCC, Halyk, Kaspi) с использованием кэширования media. | Требуется финальное подтверждение заказчика |
| **Раздел «Лестница компетенций»** | Установлена информационная заглушка («Ақпарат кейінірек қосылады»), так как детальные материалы от заказчика не поступали. | Ожидается контент от заказчика |
| **Защита онбординг-воронки (Шлюз)** | Внедрена обязательная проверка подписки на каналы при попытке перехода вглубь меню; при отсутствии подписки бот принудительно возвращает пользователя на экран проверки (`subscription`). | Реализовано в коде (`navigate_to`) |
| **Двуязычный интерфейс и синхронизация локалей** | Обеспечена полная поддержка ru/kz для всех элементов интерфейса, включая системные предупреждения (`use_menu_buttons`) и заглушки пустого FAQ (`faq_empty`). | Реализовано и проверено через тесты |
| **Автоматический контроль качества (QA)** | Внедрены автотесты (`pytest`) для проверки валидности структуры `screens.json` и синхронизации ключей в файлах локалей `ru.json` и `kz.json`. | Реализовано в коде (`test_bot.py`) |
| **Система контроля версий и CI/CD** | Проект размещен в репозитории GitHub (`Uchet_update`), настроен автоматический запуск автотестов (`pytest`) через GitHub Actions при каждом пуше. | Реализовано и настроено |

## Запросы к заказчику
1. Ожидается предоставление актуального изображения Kaspi QR для приема платежей по членским взносам.
2. Ожидается предоставление текстовых материалов по разделу **«Лестница компетенций»** для наполнения базы данных.
3. Проведена вычитка казахской локали носителем (зависит от заказчика, зафиксировано в DoD задачи I18N-1).
4. Согласование текстов системных уведомлений и заглушек на двух языках (русский / казахский).
