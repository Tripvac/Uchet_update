Инструкция по запуску и эксплуатации (OPS-2)
1. Локальный запуск и отладка
Правило одного инстанса: В продакшене должен работать строго один инстанс бота. Одновременный запуск двух ботов с одним токеном приводит к ошибке 409 Conflict.

Тестовое окружение: Локальная отладка разработчиком должна вестись исключительно с отдельным тестовым ботом (своим токеном от @BotFather) и отдельной тестовой базой данных.

Режим работы: По умолчанию локально используется Long Polling (BOT_MODE=polling), при котором бот сам автоматически очищает вебхуки на старте (deleteWebhook).

Команды для запуска:
# Установка зависимостей (включая линтеры и тесты)
pip install -r requirements.txt
pip install ruff pytest

# Создание и заполнение локального конфига
cp .env.example .env   # Для Windows: copy .env.example .env

# Применение миграций базы данных (цепочка 000 — 011)
python migrations/apply_migrations.py

# Запуск автотестов (проверка структуры экранов и локалей)
pytest

# Запуск бота
python bot.py

2. Эксплуатация на Render (Free Tier)
Сон сервиса: На бесплатном плане Render Web Service «засыпает» после 15 минут бездействия, из-за чего polling может останавливаться. Для продакшна рекомендуется переводить бота в режим вебхуков (BOT_MODE=webhook, WEBHOOK_URL, WEBHOOK_SECRET).

Пингер: Для поддержания активности настроен внешний сервис (например, UptimeRobot), который каждые ~10 минут пингует эндпоинт /health нашего Flask-приложения.

Честный /health: Эндпоинт проверяет актуальность работы фоновых процессов (возраст получения апдейтов) и общую доступность базы данных PostgreSQL, возвращая 503 при зависании.
